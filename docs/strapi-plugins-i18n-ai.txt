THE ONE EXAMPLE TO COPY
-----------------------
Official Strapi 5 company-site model (not WordPress, not plugins):

  https://strapi.io/blog/building-a-page-builder-via-content-modeling-best-practices-in-strapi5
  https://docs.strapi.io/cms/features/internationalization

That example uses five building blocks. We keep the same five:

  Collection   many entries of one kind     Projekt, Marke, Artikel
  Single       exists once                  Header, Global
  Component    a labeled form reused        SEO, Link, Hero-Slide
  Relation     same thing, many places      Projekt -> Marke, Region
  Dynamic zone editor picks section order   later, for new pages only

Rule of thumb from that guide (use this in every workshop):

  Query it? filter it? reuse it?     -> Collection + Relation
  Unique to this page/section?       -> Component
  Editors must reorder sections?     -> Dynamic zone (small list)
  Exists exactly once on the site?   -> Single type

Do NOT make "everything a component".
Do NOT make "everything a collection".
Do NOT dump 30 blocks into one dynamic zone.

     de    Deutsch     DEFAULT   (source of truth)

and free.

2. How locales work for editors
-------------------------------
Top-right of every entry: locale switch  [Deutsch | English].

Workflow (Community, no auto-translate):

  1. Editor writes and publishes DEUTSCH.
  2. Switch to English. Click "Fill in from another locale"
     and pick Deutsch. All fields copy over, including relations.
  3. Translate the copied text. Leave photos, phone, brands.
  4. Publish English separately.
     Publish is per locale. DE live does not publish EN.

Frontend fetch:
  GET /api/landings?filters[slug][$eq]=home&locale=de&status=published
  GET /api/landings?filters[slug][$eq]=home&locale=en&status=published

Missing EN: Next.js falls back to DE, never to empty page.


3. What to localize  vs  what to share
--------------------------------------
LOCALIZE  (tick "Enable localization for this field")

  title, eyebrow, intro, question, answer
  buttonLabel, caption, alt
  slug            (de: kueche-mit-insel  /  en: kitchen-with-island)
  seo.metaTitle, seo.metaDescription
  rich text bodies

DO NOT LOCALIZE  (one value for both languages)

  images / gallery          same kitchen photo
  color hex, icon enum
  phone, email, street, maps
  relations to Brand, Appliance kind, Region code
  year, sortOrder, published flags that are not copy
  CTA URL if it is a hash (#beratung) or a mailto

WHY: editors should not re-upload the Insel photo for English.
     "Fill in from another locale" then only needs text edits.

SLUG RULE (from the live Mohamed CMS):
  slug = unique Short text, lowercase, hyphens
  NOT a UID field (UID blocked extra landings before)
  Localized, so DE and EN can differ.


4. Naming so the team understands the CMS
-----------------------------------------
Two names on every type / component / field:

  displayName   German, human     "Kuecheninsel"  "Ablauf-Schritt"
  API name      English, stable   kitchen-island  process-step

MCP and Next.js always see the English API name.
Editors only see German displayName + description.

Always fill Description, e.g.:
  "Ein Schritt im Ablauf 'So entsteht Ihre Kueche'.
   Vier Stueck auf der Startseite."

Icon: pick one per component (picture, layer, puzzle).
Later: component preview image so the dynamic-zone picker
looks like the real section.

Categories (the folders editors see):

  shared     atoms used everywhere     seo, media, link, rich-text
  landing    homepage / campaign       hero, kacheln, ablauf, faq
  header     navigation                menu, group, link, teaser
  project    Referenzkueche            spec, gallery-item
  geraete    appliance copy            (later)

Keep the starter components that already exist:
  shared.seo   shared.media   shared.quote
  shared.rich-text   shared.slider


5. Component model for BEER  (team-readable)
--------------------------------------------
Homepage stays NAMED SECTIONS, not a free page builder.
The team already knows Hero, Kacheln, Ablauf, Entdecken, FAQ,
Beratung. Do not hide those inside a dynamic zone.

SINGLE  Header
  logo (media, not localized)
  logoAlt (localized)
  ctaLabel, ctaUrl (label localized, url usually not)
  menus[]  -> header.menu

  header.menu
    label, title, href, intro, variant
    groups[] -> header.group
    teasers[] -> header.teaser

  header.group
    title
    links[] -> header.link     (label localized, href shared)

  header.teaser
    caption, alt (localized)
    image (shared)
    href

COLLECTION  Landing
  title, slug (localized)
  seo -> shared.seo
  hero -> landing.hero
  kacheln -> landing.kacheln
  ablauf -> landing.ablauf
  entdecken -> landing.entdecken
  faq -> landing.faq
  beratung -> landing.beratung

  landing.hero
    slides[] -> hero.slide     image shared, alt localized

  landing.kacheln
    eyebrow, intro (localized)
    colors[] -> kacheln.color-tile
      title, href, alt, color, image

  landing.ablauf
    eyebrow, title, buttonLabel, buttonHref
    steps[] -> landing.process-step
      step, title, description, icon (enum, not localized)

  entdecken.panel
    title, subtitle, buttonLabel, href, alt, image

  landing.faq-item
    question, answer

  landing.beratung
    copy localized; address / phone / email shared

Nesting max TWO levels (Landing -> kacheln -> color-tile).
Deeper than that and editors + MCP both get lost.

  brand             Bora, Miele, Gaggenau, Quooker
  furniture
  region
  faq-item          global FAQ, not only homepage
  article, author, category   KEEP starter blog

Project relations (this is the engine of the site):
  project  many-to-many  style, shape, color, island,
                         material, appliance, brand, region

A leaf URL like /kuechen/stile/landhaus is then:
  short intro from kitchen-style
  + filtered projects
not a duplicate landing for every style.


7. Dynamic zone  (later, small, curated)
----------------------------------------
Only when we add pages that are not the homepage and not a
cluster filter. Allowed blocks, nothing else:

  blocks.hero
  blocks.rich-text
  blocks.faq-list          relation to faq-item[]
  blocks.project-grid      relation to project[]
  blocks.cta
  blocks.media

Official warning we follow: a dynamic zone is not a dumping
ground. Deep nesting inside those blocks kills performance
and confuses the team.

Homepage does NOT use this zone.


8. Where AI actually lives  (free, self-hosted)
-----------------------------------------------
Not inside a paid Strapi feature. Two free pieces:

  A. Content-Type Builder in the admin
     We (or Christian) click the schema from this playbook.
     German displayName, English API name, descriptions.

  B. Cursor + Strapi MCP  (self-hosted, Community, 5.47+)
     Enable mcp in server config.
     Admin token: draft create/update only. NO publish.
     Locale in every prompt: "in German (locale de)".
     MCP cannot upload files; photos stay in Media Library.
     MCP is weak on deep dynamic zones — another reason our
     homepage uses named components.

What Cursor can help with, still as drafts:

  Schema prompts we already wrote in this file
  German -> English copy after "Fill in from another locale"
  Alt-text suggestions the editor pastes into Media Library

Do not let any agent publish. Draft only. Human publishes.

Brand names that must never be "translated":
  BEER, Bora, Miele, Gaggenau, Quooker, Fenix, Taj Mahal

10. Next.js contract  (when we wire routes)
-------------------------------------------
  Default locale de, prefix-less:   beer.de/kuechen/...
  English:                          beer.de/en/kuechen/...
  Fetch with ?locale=
  Populate nested components explicitly (Strapi 5 has no
  shared populate=* for components).
  hreflang de + en + x-default=de
  Fallback: if EN missing, render DE and noindex the EN URL.
